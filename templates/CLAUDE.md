# Templates, screens and assets

Every page extends `base.html.twig` (blocks `title`, `description`, `content`, `stylesheets`, `head`, `javascripts`), which includes `layout/_navbar`, `_admin_menu`, `_flash` and `_footer`. `App\Twig\AppExtension` provides the globals `site` (`SiteConfig`: use it instead of hard-coded site details), `counters` (lazily queried admin menu counts) and `app_version` (`SiteConfig::VERSION`: the `generator` meta tag in `base.html.twig` and the bare 404 page, and the footer's centred last line) and the functions `csp_nonce()` and `profile_image_url()`. Link with `path('route')`, never hard-coded URLs. Controllers flash with `addFlash('info'|'danger', …)`; `_flash` reads flashes only from an existing session, so anonymous pages without a form start none and error pages render while the database is down.

- The administration bar (`layout/_admin_menu.html.twig`) is data-driven: each item names the permission its controller's `#[IsGranted]` requires and shows only when `is_granted()` allows it, and every group and item names its own Bootstrap Icons `icon` (owner decision 2026-10-27: every menu item has one; `LayoutTest` checks it). Likewise show actions and links to protected pages only with `is_granted()` of the target's permission; this is a navigation aid, the controller is the boundary.
- Styling: Bootstrap 6 classes first (6.0.0-alpha.1; its documentation is at getbootstrap.com/docs/6.0, and the v5 names differ: `md:col-6` not `col-md-6`, `btn-solid theme-primary` not `btn-primary`, `fg-*` not `text-*`, and a spacing scale where `mb-5` is 1rem). `assets/styles/app.css` is a small application layer (`app-narrow` for single-purpose forms) inside Bootstrap's `custom` cascade layer, because v6 utilities are not `!important` and rules outside a layer would beat them. The page is always `data-bs-theme="light"`. Icons are Bootstrap Icons (`bi bi-*`) only. No inline `style=`, `<script>` or event handlers: the CSP refuses them.
- Message HTML is never printed `|raw`; the public archive uses the `app.message_html` sanitizer.
- The acceptable use policy and privacy pages (`page/policy.html.twig`) print `App\Util\Markdown`'s rendering of `docs/AUP.md` and `docs/PRIVACY.md`, passed as `Twig\Markup`: the renderer escapes all of the document's text and emits no inline style, and `PageController` fills the document's placeholders with escaped Settings values (list name, domain, organisation). On the acceptable use policy the page shows one address only, the policy's `abuse@<domain>`: `PageController` passes `footer_without_administrator`, and `layout/_footer.html.twig` then omits the administrator's link (the privacy policy keeps it, and sends requests to that same administrator's address). It is the only other HTML that is not autoescaped.
- Client errors render the site's error templates (`bundles/TwigBundle/Exception/`) even with `APP_DEBUG=true` (`App\Twig\ErrorPageDebug`); only 5xx errors show Symfony's exception page in debug mode.

**Screen conventions** (administration pages follow them; see `admin/messages.html.twig`):
- header: `{% embed 'layout/_page_header.html.twig' with {title, description} %}` with an `actions` block (primary action first, `btn-solid theme-primary`; secondary `btn-outline theme-secondary`);
- filters: a `form.card.card-body.bg-1` (`role="search"`) with Search and Clear;
- tables: `.table-responsive > table.table.table-hover.align-middle` (app.css tints every `thead`), `scope="col"`, numbers `text-end`, row actions in a right-aligned `btn-group-sm`;
- empty results: `{% include 'layout/_empty_state.html.twig' with {message, icon, hint} %}` instead of an empty table;
- status badges: the macros in `admin/_macros.html.twig`. Data reaches Twig structured (e.g. `SubscriberRepository::reportPage()` returns each row's `memberships` as `{name, state}` pairs); never parse display strings in templates;
- forms: grouped in cards with the submit row in the footer (or a bordered row at the end), help text in `form-text` linked by `aria-describedby`, required fields marked `*`;
- cards, card headers and alerts are flex containers in v6: put text in a `<p>` or `<div>` inside them (loose text beside inline elements becomes separate items), and add `flex-row` to a header or body that lays its children out side by side;
- buttons: starting delivery is `btn-solid theme-success`, stopping `theme-warning`, removing or suppressing `btn-solid theme-danger`/`btn-outline theme-danger`. Forms that delete, clear or suppress carry `data-confirm="Question?"` (handled in `assets/app.js`) and stay POST + CSRF;
- a form that must be submitted as soon as its page loads carries `data-autosubmit` (the Finish step of a mail service connection, whose page arrives by a GET from the mail service); it keeps its visible button;
- a value someone copies elsewhere (an address to paste into another site, a DNS record) gets a copy button (owner decision 2026-10-27): `{% include 'layout/_copy.html.twig' with {value, id, label} %}` draws it in `<code>` with a button that `app.js` shows and wires (`data-copy`: the clipboard, or the text selected where the clipboard is refused); without JavaScript the button stays hidden and the value can be selected;
- POST outcome pages: `page/result.html.twig` (`title`, `message`, optional `links` of `{label, route, permission}`);
- pagination: `_pagination.html.twig` with `App\Http\Pagination` (v5 `?r=` rows per page), keeping the filters in `query`.

**htmx.** htmx 4.0.0 (`assets/lib/htmx`, imported by `assets/app.js`; configured by the `htmx-config` meta tag in `base.html.twig`: indicator styles in `app.css`, the `data-hx-` prefix off) updates administration pages in part. Read the guides in the `htmx.org@4.0.0` npm package's `dist/skills/` (htmx 4 differs from 2: inheritance is explicit with `:inherited`, event names have colons, every status swaps) before changing it.
- A part of a page that htmx draws again is a **region**: its own template (`admin/_<name>.html.twig`), which draws one element with the region's id and class `app-region` (and imports what it needs: it is also rendered alone). The page includes it; the controller renders the page with `RendersRegions::renderPage($request, $view, [region id => template], $params)`, which answers an htmx request for a region (`App\Http\Htmx::region()`: `HX-Request`, `HX-Request-Type: partial`, `HX-Target`) with the region alone plus the flash messages (`layout/region.html.twig`, an `<hx-partial>` for `#app-flash`). Every other request, htmx's history restore and a browser without JavaScript included, gets the page. No route exists only for a region.
- The attributes are the macros of `layout/_htmx.html.twig`: `search(action, region)` on a GET filter form (300 ms after the last change; the Search button is in `<noscript>`, with an `htmx-indicator` "Searching…"), `pager(region)` (pass `region` to `_pagination.html.twig`), `post(action, region)` on an action form, `refresh(url, region, every)` on a region that redraws itself (outerMorph) while something is in progress: it leaves the attributes out once nothing is left to wait for. A Symfony `form_start()` takes the same attributes in its `attr` map. Macros imported at the top of a page are not visible inside an `{% embed %}` block: import them inside it.
- An action keeps its POST + CSRF and its post/redirect/get; it redirects with `redirectAfterAction()`, which for htmx returns to the page the button was pressed on (`HX-Current-URL`: search and page kept), and htmx follows the redirect to that page's region. A refused form answers 422 with the region and its errors (`app.js` lets 422 swap; any other 4xx or 5xx, or a whole page where a region was asked for, opens the page instead, or says the action failed). `data-confirm` is answered in the capture phase, before htmx sends.
- Never `hx-on`, `js:` values or trigger filters (`[...]`): they need `eval`, which the CSP refuses. Authored message HTML (the archive, the editor) is inside `hx-ignore`. A form never sits inside another form: browsers drop the inner one (`SmokeTestCase::assertCleanPage()` checks every page).
- A region that refreshes itself on a timer is left out of the Site Log for a signed-in user (`Htmx::refreshesItself()`, `SiteLogListener::NOT_LOGGED`). A refresh reads what is stored; a GET still changes nothing (the worker asks catto-mail).

**Forms.** The form theme `form/theme.html.twig` (the application's own Bootstrap 6 theme on Symfony's `bootstrap_base_layout.html.twig`, set in `config/packages/twig.yaml`) renders each row as a `.form-field` (choices shown as radios or checkboxes as a `.form-group`), selects as `.form-control`, checkboxes as `.check` and radios as `.radio`, and gives every widget `aria-describedby` (help and errors) and `aria-invalid`, gives forms `novalidate` (validation is server-side only) and marks required labels with the asterisk. Lay fields out with `form_row()` in the screen's grid (see `admin/message_form.html.twig`); render choices by hand only to add descriptions (subscribe page, role permissions) or to put them in a menu of checkboxes (the lists in `admin/message_form.html.twig`: a `.form-control.form-control-caret` button toggling a `.menu.app-checklist[data-checklist]`, whose ticked choices `app.js` names on the button), keeping `form_errors()`. Password fields always render empty. The sign-in and subscribe forms carry the bot trap (`BotTrapType`, named `BotCheck::TRAP_FIELD`): render it with `form_row()`; its row gets `.app-trap` (off-screen, not `display: none`) and `aria-hidden`, its input `tabindex="-1"`.

**Assets.** AssetMapper maps `assets/` (`config/packages/asset_mapper.yaml`, `importmap.php`), and `{{ importmap('app', {nonce: csp_nonce()}) }}` loads `assets/app.js`. Stylesheets, including `styles/app.css` and the vendored `lib/bootstrap*`, are `<link>`ed with `asset()`: a CSS import from JavaScript becomes a `data:` script URL that the CSP refuses. Bootstrap's JavaScript is an ES module with no global: `app.js` imports what it needs from `./lib/bootstrap/bootstrap.bundle.min.js`, and htmx from `./lib/htmx/htmx.esm.min.js`. Bootstrap, Bootstrap Icons and htmx are unmodified distribution files in `assets/lib/` (sources and hashes in `assets/lib/README.md`). No CDN, Node/npm or jQuery. In debug mode PHP serves `/assets/*`. `app.js` sets up content that arrives with `htmx.onLoad()` (the first page included), so what it does to a page also happens to a region drawn later.

**CKEditor 5** is a prebuilt bundle in `public_html/vendor/ckeditor5/` (with its emoji list, so nothing comes from CKEditor's CDN). It loads only on pages extending `admin/_editor_page.html.twig`; `assets/ckeditor/editor.js` attaches it to the textarea marked `data-html-editor` (the HTML part of `MessageType`/`TemplateType`). Editor routes set the `_csp` default `ContentSecurityPolicy::EDITOR`.

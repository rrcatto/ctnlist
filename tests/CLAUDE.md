# Tests

Suites (`phpunit.dist.xml`, which also sets the test environment variables): `tests/Unit` (plain PHPUnit), `tests/Integration` and `tests/Smoke` (HTTP against the running stack). Run them through `bin/dev test`; they run as root in the app container (`bin/dev test` first makes `var/cache` www-data-owned so PHP-FPM can still build its cache).

**Integration** tests extend `IntegrationTestCase`: the kernel in the `test` env against the `ctnlist_test` database, each test inside a rolled-back transaction. Create the rows you need (`createSubscriber()`, `createList()`, `setMembership()`, `createMessage()`). Mail goes to the null transport; use Symfony's mailer assertions. Every `App\` service is public in the test container (`Kernel::build()`), so tests can fetch services nothing uses yet, and `tests/bootstrap.php` recompiles the container on every run. Forms can be built from `FormFactoryInterface` (see `Integration/Form/SettingsFormTest.php`). For catto-mail, see `src/CattoMail/CLAUDE.md` (`fakeCattoMail()`). The banlist checker is tested against `ctnlist_banlist_test` (`dev/podman/banlist-test.env`).

**Smoke** tests run over HTTP against the smoke installation (`/var/www/ctnlist-smoke`, `http://web:8081`, database `ctnlist_smoke`), never the development one: `bin/dev test` drops, migrates and seeds `ctnlist_smoke` first, `SmokeTestCase` refuses any other database and a `SMOKE_BASE_URL` that does not serve it, `IntegrationTestCase` any database but `ctnlist_test`, and `bin/dev check` fails if the development database's row counts changed.
- The smoke database starts with the `ALL` list and `admin@ctnlist.test` only, so each test class creates its own fixtures (subscribers `smoke-<name>@ctnlist.test`). Subscribers with consent events cannot be deleted (append-only table) and need not be: they vanish with the database. Never delete consent or audit rows to clean up, and delete only the roles a test created, never a subscriber's `subscriber` role.
- `SmokeTestCase` helpers: `client()`, `request()`, `issueLoginToken()`, `signInWithLink()` (open the link's page, then POST its Sign in form), `loginAsAdmin()`, `csrfToken()`; for forms `formFields()` (what a browser submits), `submitForm()` (load a page and submit one of its forms with overrides, e.g. `['list[name]' => 'x']`) and `submitAndFollow()` (expects the post/redirect/get success and returns the next page, or fails with the form's errors). `withSetting()` runs a block with a Settings override and restores the installation's own value. After every class, `tearDownAfterClass()` asserts the system data is intact (system roles, `ALL`, every subscriber's `subscriber` role, the dev administrator, the Administrator role's permissions).
- Form tests assert the field error id (`<form>_<field>_error1`), that the entered values are kept and that nothing was stored.
- `RouteSmokeTest` requests every GET route anonymously and as `admin@ctnlist.test` (logged in by inserting a magic-link token), creating and deleting its own fixtures; every new GET route must be added to it.
- `SettingsPageTest` needs `APP_SETTINGS_KEY` in `dev/podman/ctnlist.env` (`bin/dev up` adds it) and restores any existing overrides afterwards.
- The app writes timestamps in PHP's timezone (Africa/Johannesburg) while PostgreSQL runs in UTC: compute timestamps in PHP when inserting rows the app compares against `date()`.

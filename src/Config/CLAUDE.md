# Configuration and Settings

`SiteConfig` holds the non-secret installation settings with the v5 defaults and fallbacks. `SiteConfigFactory` builds it from `RuntimeSettings::environment()`, which excludes secrets, and templates get it as the Twig global `site`.

**Settings overrides.** `RuntimeSettings` resolves each env var listed in `SettingsCatalogue` as database override → `.env` → the catalogue's `default`. Overrides live in `options` under `setting:<ENV_NAME>` (`SettingRepository`). `.env` is never written, and saving the inherited value (or "Reset override"/"Reset section") deletes the override. Changes apply from the next request or email.
- Read these settings through `SiteConfig` or `RuntimeSettings::get()`/`int()`, never `%env()%` or `#[Autowire(env:)]`. A service that needs a setting at use time is built lazily (e.g. `SmtpServerPool` by `SmtpServerPoolFactory`, which receives the decrypted `MAILER_DSN`).
- A period of time is the `duration` type (`App\Util\Duration`, `1y1w1d1h1m1s`): its default and `shortest` are periods too, it is read with `RuntimeSettings::duration()`, and the form refuses anything that is not a period or is shorter. A period that only `.env` sets is read with `Duration::setting()` (default and minimum) and listed in `DiagnoseCommand::ENV_PERIODS`.
- To add a setting, add it to the catalogue with its type, validation bounds and default (`width`, `heading` and `tab` lay out the form), then read it as above. Validation rules per type are in `App\Form\Settings\SettingConstraints`: e.g. `url` accepts only a full `http(s)://` address (`https` only with the catalogue's `https` flag), and one-line types refuse CR/LF.
- Infrastructure stays out of the catalogue: secret keys, `CATTOMAIL_*` (except the mail service's address, below), `DB_*`, `GDB_*`, the suppression provider, URLs, paths, cookie names, `APP_ADMIN_EMAIL`, `APP_TIMEZONE`, `TRUSTED_PROXIES`.
- The store also holds the mail service connection (`App\CattoMail\ConnectionStore`: `setting:CATTOMAIL_API_KEY`, `setting:CATTOMAIL_WEBHOOK_SECRET`, `setting:CATTOMAIL_CONNECTION`). Those are written only by Connect and Disconnect, are not in the catalogue, and resolve the other way round: `.env` wins over the stored value (`CattoMailConfigFactory`). `RuntimeSettings` ignores them.
- The mail service's address, `setting:CATTOMAIL_API_BASE_URL`, is both: the catalogue's group `mail_service` (owner decision 2026-10-27: `.env` sets it, the Settings page can change it) and the address a connection was made with, under the same key so that an installation connected before keeps working. The stored value wins over `.env`, except when `.env` also sets the key (a hand-made `.env` configuration stays whole). Connect writes it, Disconnect keeps it, and `SettingsController` refuses to change or reset it while a connection is stored (`ConnectionStore::isConnected()`; the page shows it read-only).
- The Settings page (`Admin\SettingsController`, `settings.manage`) has one Symfony form per tab: `SettingsGroupType` built from the catalogue, the transactional SMTP server as the nested `SmtpServerType`, and `SettingsFormData` converting between settings and form data. Invalid input is shown at its field and nothing in that tab is saved. The SMTP and Mail service tabs (`SettingsController::ADMINISTRATOR_ONLY`) are shown to and saved by administrators only, whatever else `settings.manage` allows: the SMTP server receives every sign-in link, and the mail service every campaign.

**Secrets.** The secret setting `MAILER_DSN`, and the connection's API key and webhook secret, are encrypted by `SettingsCipher` (AES-256-GCM with `APP_SETTINGS_KEY`, 32 random bytes in Base64; stored as `enc:v1:<key id>:<base64(nonce|tag|ciphertext)>`). None of them is ever loaded into a form, rendered (password fields stay empty, and an empty field keeps the current value) or logged. A secret that cannot be decrypted raises `SettingsCipherException` when mail needs it, and the Settings page shows the problem; there is no fallback.

**Production readiness.** `ProductionReadiness` holds the rules of `ctnlist:diagnose --production` (automatic under `APP_ENV=prod`; ERROR lines exit 1; it sends no mail, calls no external service and prints no secrets). Settings ctnlist no longer reads are listed in `DiagnoseCommand::OBSOLETE`, kept in step with `OBSOLETE_ENV` in `bin/dev`.
